# Хранилище: интерфейс

Тикет: [Хостинг, адаптер и форма серверного слоя](../../.scratch/training-webapp/issues/09-hosting-i-serverniy-sloy.md). Термины по `CONTEXT.md`, таблицы в [data-model.md](./data-model.md).

## Зачем

Приложение не должно знать, где лежат данные. В фазе 1 они в IndexedDB на устройстве, в фазе 2 в Postgres. Меняется реализация, не код приложения.

Интерфейс называет операции предметной области, а не строки таблиц. Ни `insert`, ни `select`, ни `findOne`. Если операция читается как обращение к базе, она названа неправильно.

## Почему две реализации, а не одна

Файловая система Deno Deploy работает только на чтение, персистентности нет. Каталоги в jsonl уезжают вместе с деплоем и читаются оттуда. Записать на сервере нечего.

Поэтому в фазе 1 всё изменяемое живёт в IndexedDB на устройстве, а сервер отдаёт каталог и собирает Занятие, не держа состояния. В фазе 2 появляется управляемый Postgres от Deno Deploy, и та же реализация переезжает на сервер.

## Слои

```
Приложение
    │
    ├── Сборка занятия          чистая функция, состояния не имеет
    │
    └── Хранилище               интерфейс ниже
            ├── IdbStore        фаза 1, IndexedDB в браузере
            └── PgStore         фаза 2, Postgres на сервере
```

Сборка Занятия в Хранилище не входит. Это чистая функция, описанная в [session-assembly.md](./session-assembly.md). Хранилище даёт ей вход и принимает результат.

## Интерфейс

```ts
interface Store {
  // ── Каталог. Только чтение, в фазе 1 приходит с сервера ──────────────

  /** Группы мышц, Мишени и Упражнения одного Режима. */
  catalogOf(modality: Modality): Promise<Catalog>;

  /** Программа целиком: Блоки, Закрепления, Добор, противопоказания. */
  programOf(programId: Id): Promise<Program>;

  /** Что показать Аккаунту на его странице. */
  programsFor(account: Id): Promise<ProgramCard[]>;

  // ── Аккаунт ──────────────────────────────────────────────────────────

  /** Заводит Аккаунт по никнейму и почте. Почта ещё не подтверждена. */
  registerAccount(nickname: string, email: string): Promise<Account>;

  accountByEmail(email: string): Promise<Account | null>;

  /** Выпускает код подтверждения и отправляет его на почту. */
  issueEmailCode(account: Id): Promise<void>;

  /** Проверяет код и отмечает почту подтверждённой. */
  confirmEmail(account: Id, code: string): Promise<boolean>;

  renameAccount(account: Id, nickname: string): Promise<void>;

  // ── Ключи и Сеансы ───────────────────────────────────────────────────

  /** Привязывает новый passkey к Аккаунту. */
  attachKey(account: Id, key: NewCredential): Promise<Credential>;

  keysOf(account: Id): Promise<Credential[]>;

  /** Открывает Сеанс на этом устройстве. */
  signIn(account: Id, key: Id, device: string): Promise<AuthSession>;

  /** Сеансы Аккаунта на всех устройствах, для меню по аватару. */
  sessionsOf(account: Id): Promise<AuthSession[]>;

  revokeSession(session: Id): Promise<void>;

  /** Гасит все Сеансы кроме текущего. Для потерянного устройства. */
  revokeOtherSessions(account: Id, keep: Id): Promise<void>;

  // ── Список Аккаунтов на устройстве ───────────────────────────────────

  /** Кто входил на этом устройстве. Для меню по аватару. */
  knownAccounts(): Promise<DeviceAccount[]>;

  /** Убирает запись из списка. Данные Аккаунта не трогает. */
  forgetAccount(account: Id): Promise<void>;

  // ── Занятие ──────────────────────────────────────────────────────────

  /** Активное Занятие, если оно есть. Не больше одного на Аккаунт. */
  activeSession(account: Id): Promise<Session | null>;

  /** Кладёт собранное Занятие и делает его активным. */
  openSession(session: NewSession): Promise<Session>;

  /** Отмечает Упражнение выполненным или пропущенным. */
  markExercise(session: Id, ord: number, status: ItemStatus): Promise<void>;

  /** Заменяет позиции после пересборки. Увеличивает счётчик сборок. */
  redrawn(session: Id, items: SessionItem[]): Promise<void>;

  /** Закрывает Занятие: завершено, отменено или протухло. */
  closeSession(session: Id, state: SessionState): Promise<void>;

  /** Сдвигает отметку активности. От неё считаются два часа простоя. */
  touchSession(session: Id): Promise<void>;

  // ── История ──────────────────────────────────────────────────────────

  /** Выполненные Упражнения за окно новизны. Вход для сборки. */
  recentExercises(account: Id, days: number): Promise<Performed[]>;
}
```

## Правила

**Хранилище не считает.** Веса новизны, отбор, фильтр противопоказаний, порядок Блоков это сборка Занятия, не Хранилище. Хранилище только хранит и отдаёт.

**Хранилище не знает про сеть.** Реализация решает, лежат данные рядом или за запросом. Приложение об этом не спрашивает.

**Каждая операция возвращает предметный объект, а не строку таблицы.** `Session` содержит свои позиции, `Program` содержит свои Блоки. Собирать целое из кусков это работа реализации.

**Ошибки предметные.** Не «нарушено ограничение уникальности», а «почта уже занята». Не «запись не найдена», а «Занятие уже закрыто».

**Одинаковый контракт у обеих реализаций.** Набор тестов пишется один раз против интерфейса и прогоняется на обеих. Это единственная гарантия, что переезд на Postgres ничего не сломает.

## Что остаётся снаружи

Отправка письма с кодом. Это внешняя служба, а не хранилище. Интерфейс объявляет `issueEmailCode`, реализация зовёт почтовую службу. В фазе 1 заглушка код никуда не шлёт.
